# Помощник проектного отдела iiko

Telegram-бот отвечает по локально сохранённым статьям iikoHelp. Его бизнес-логика не зависит от Telegram: другой адаптер, например MAX, должен только передавать сообщения в `SupportService` и отображать его ответы.

## Что уже реализовано

- личные сообщения: краткий ответ и кнопка на исходную статью iikoHelp;
- группы: молчание в рабочее время, одно уведомление за непрерывный нерабочий период и команда `/a вопрос` вне рабочего времени;
- «Не помогло»: одно нажатие создаёт локальное обращение без дублей и подтверждает, что проектный отдел поможет, когда будет на связи;
- SQLite + FTS5: текст статей, ссылки, вопросы, уведомления, feedback и обращения;
- загрузка только с `howto.iiko.help` и `ru.iiko.help`, включая проверку редиректов;
- поиск по смысловым ключам в своей базе: бот отбрасывает служебные слова и отвечает на каждое новое сообщение независимо от предыдущих;
- DeepSeek (необязательно) формулирует краткий ответ только по найденной статье; любой такой ответ обязательно сопровождается кнопкой на iikoHelp. Вопросы об установке, лицензиях и рабочих местах без подходящей статьи могут получить осторожный общий ответ без ссылки;
- если для точного ответа нужен продукт, Telegram предлагает кнопки iikoOffice, iikoFront, iikoChain и iikoWeb и повторно отвечает на исходный вопрос после выбора. Очевидные признаки (например, «кассир», «кассовая смена на терминале») бот распознаёт сам; кнопка «Не знаю» спрашивает понятным языком, где выполняется действие;
- одиночный, массовый и повторный импорт статей.

`config/production_calendar.json` содержит рабочие часы, переносы и сокращённые дни. Суббота, воскресенье и фиксированные государственные праздники РФ учитываются в коде. В файл уже внесён утверждённый производственный календарь РФ на 2026 год: дополнительные дни отдыха 9 января, 9 марта, 11 мая и 31 декабря, а также сокращённые дни 30 апреля, 8 мая, 11 июня и 3 ноября.

## Быстрый запуск

Нужен Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
cp .env.example .env
```

В `.env` локально задайте `TELEGRAM_BOT_TOKEN`. `DEEPSEEK_API_KEY` необязателен. Файл `.env` исключён из Git и не должен пересылаться в чат.

Создайте бота в BotFather, скопируйте токен в `.env`, затем выполните в BotFather `/setprivacy` и отключите Group Privacy. После изменения удалите бота из тестовой группы и добавьте снова: иначе Telegram не отдаст ему первое обычное сообщение, нужное для нерабочего уведомления.

Запуск:

```bash
.venv/bin/python -m iiko_assistant.telegram_adapter
```

## База знаний

До запуска бота сначала наполните базу. Пример импорта одной статьи:

```bash
.venv/bin/python -m iiko_assistant.import_article \
  --url "https://howto.iiko.help/articles/#!iikofront/getting-started" \
  --from-iikohelp \
  --title "Кассовое приложение iiko"
```

Для 100–300 наиболее частых тем составьте свой список URL: по одному разрешённому публичному URL на строку. Шаблон — [`config/articles.example.txt`](config/articles.example.txt).

```bash
.venv/bin/python -m iiko_assistant.bulk_import \
  --urls-file config/articles.txt
```

Чтобы наполнить базу из официальных sitemap’ов всех разрешённых разделов, сохранив только статьи с версией 8.8 и новее (а также актуальные разделы без версии), используйте:

```bash
.venv/bin/python -m iiko_assistant.sitemap_import --min-version 8.8
```

Команда работает последовательно с короткой паузой между загрузками и продолжает работу при ошибке отдельной статьи. Перед записью можно проверить объём выборки с `--discover-only`.

Обновление всей уже импортированной базы:

```bash
.venv/bin/python -m iiko_assistant.refresh_articles
```

Последнюю команду можно запускать по расписанию, например ночью. Она продолжит обновление, даже если отдельная статья временно недоступна, и вернёт ненулевой код, чтобы мониторинг заметил ошибку.

## Поведение бота

| Контекст | Рабочее время (08:00–17:00 МСК, рабочие дни РФ) | Нерабочее время |
| --- | --- | --- |
| Личные сообщения | Ответ по базе знаний, ссылка на статью | То же |
| Обычное сообщение в группе | Полное молчание | Одно уведомление до ближайшего открытия |
| `/a вопрос` в группе | Полное молчание | Ответ, ссылка и «Не помогло» |

Только автор группового вопроса может нажимать «Не помогло». Первое нажатие создаёт локальное обращение; повторные клики не создают дубли. На этом этапе направление обращений во внешнюю систему ещё не подключено: записи хранятся в `support_requests` SQLite.

## Устройство проекта

```text
Telegram / будущий MAX
        │
        ▼
  SupportService ───── BusinessCalendar
        │
        ├────────────── KnowledgeBase ──── DeepSeek (необязательно)
        ▼
      Database (SQLite + FTS5)
        │
  статьи · вопросы · feedback · обращения · уведомления
```

- `src/iiko_assistant/service.py` — сценарии поддержки, без зависимости от мессенджера.
- `src/iiko_assistant/telegram_adapter.py` — тонкие Telegram-обработчики и inline-кнопки.
- `src/iiko_assistant/database.py` — SQLite-схема и FTS5-поиск.
- `src/iiko_assistant/knowledge.py` — retrieval-first ответы и безопасный fallback.
- `src/iiko_assistant/iikohelp.py` — разрешённые домены и получение Markdown.
- `src/iiko_assistant/bulk_import.py` и `refresh_articles.py` — наполнение и обновление базы.

Для production следующим шагом нужен отдельный адаптер хранилища PostgreSQL: те же операции `articles`, `questions`, `feedback`, `support_requests` и `group_notifications`, плюс `pgvector`/эмбеддинги для семантического поиска. Этот переход не должен затрагивать `SupportService` или адаптеры мессенджеров. Также понадобятся: утверждённый производственный календарь, интеграция с Planfix/Jira/CRM, резервные копии, секреты, логи и мониторинг.

## Проверка

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

В проекте нет токенов, реальной базы статей и внешнего маршрута обращений — это нужно настроить в следующем рабочем этапе.
